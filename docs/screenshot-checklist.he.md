# רשימת צילומי מסך — BloodBank BECS

הרשימה מבוססת על מסכי הממשק בקוד הנוכחי: 9 מסכים לאחר התחברות, ומסך התחברות אחד. חלק מהסעיפים הם אזורים או מצבים באותו מסך, ולא עמודים נפרדים.

## הכנה

- להשתמש בנתוני הדגמה סינתטיים ובגודל חלון אחיד.
- להשאיר בצילום את כותרת המסך ואת התפקיד שבסרגל הצד.
- במסכים ארוכים לצלם את כל העמוד, או כמה צילומים חופפים המכסים גם את החלק התחתון.
- לצלם הודעות הצלחה ושגיאה לפני מעבר למסך אחר.
- לצלם מצבים הדורשים שינוי נתונים באמצעות חשבונות ונתוני הדגמה.

## 1. התחברות — Login

- [ ] מסך ההתחברות הרגיל.
- [ ] מסך ההתחברות עם הודעת שגיאה לאחר פרטים שגויים.

## 2. מלאי — Inventory — כל התפקידים

בכל צילום לכלול את כרטיסי הסיכום, המלאי לפי סוג דם, טבלת סוג דם וסטטוס, וסיכום הסטטוסים לכל המוצרים.

- [ ] מלאי PRBC.
- [ ] מלאי FFP.
- [ ] מלאי Platelets.
- [ ] מלאי Cryoprecipitate.
- [ ] תצוגת RESEARCHER, שבה התפריט כולל מלאי בלבד.

## 3. קליטת תרומה — Donation intake — OPERATOR

- [ ] טופס Register a donation, כולל פרטי תורם, סוג דם ותאריך ושעת איסוף.
- [ ] הצלחת רישום תרומה והצגתה בהסגר.
- [ ] אזור Produce components עם בחירת תרומה ותבנית Red cells + plasma.
- [ ] אותו אזור עם התבנית Red cells + plasma + platelets.
- [ ] הצלחת ייצור רכיבים, עם הרכיבים שנוצרו ומצבם.
- [ ] טבלת Donation work list.
- [ ] כרטיס Donation details and components שנפתח בלחיצה על מזהה תרומה, לפני ייצור רכיבים.
- [ ] אותו כרטיס לאחר ייצור רכיבים, כולל מוצר, גרסת פרופיל, סטטוס, תוקף ואחסון.

## 4. רכיבי דם — Blood components

המסך זמין ל־OPERATOR, LAB, DISPENSER ו־ADMIN. ל־OPERATOR יש פעולות ייצור Cryo והשלמת רשומה ישנה; OPERATOR ו־LAB יכולים לפסול רכיבים; ADMIN ו־DISPENSER צופים בלבד.

- [ ] הרשימה המלאה עם עמודות תוקף, אחסון ופעולות, כ־OPERATOR.
- [ ] תצוגת LAB עם פעולת Discard.
- [ ] תצוגת צפייה בלבד כ־ADMIN או DISPENSER.
- [ ] תוצאות סינון לפי מוצר, סוג דם וסטטוס, וחיפוש לפי מזהה רכיב או תרומה.
- [ ] דוח Expiry within seven days כשהאפשרות מסומנת.
- [ ] תוצאה ריקה — No matching components.
- [ ] דוגמאות לסטטוסים Available, Quarantined, Expired, Dispensed, Processed ו־Discarded, ככל שקיימים בנתוני ההדגמה.
- [ ] טופס Discard פתוח עם שדה סיבה וכפתורי אישור וביטול.
- [ ] תוצאת פסילה: הודעת הצלחה ורכיב Discarded עם הסיבה.
- [ ] לאחר Produce cryo: רכיב Cryoprecipitate עם קישור למקור, ורכיב FFP המקורי במצב Processed.
- [ ] טופס Complete a legacy record, אם קיימת רשומת LEGACY בהסגר.
- [ ] הצלחת שמירת פרטי LEGACY מאומתים, כשהרכיב נשאר בהסגר, אם קיימים נתונים מתאימים.
- [ ] עמוד נוסף ברשימה, אם יש יותר מ־100 תוצאות.

## 5. מעבדה — Laboratory — LAB

- [ ] Laboratory work queue ו־Donation work list, לפני בחירת תרומה.
- [ ] תרומה נבחרת וכרטיס הפרטים והרכיבים שלה.
- [ ] טופס Record or correct a result כאשר הבדיקה היא ABO_RH.
- [ ] אותו טופס בבדיקת סקר, עם אפשרויות Nonreactive, Reactive, Indeterminate ו־Pending; אפשר לפתוח את הרשימה לצילום.
- [ ] אזור Release decision עם תוצאות חסרות או חוסמות, והודעת שגיאה בניסיון אישור שאינו עומד בדרישות.
- [ ] כל הבדיקות הנדרשות תקינות, יחד עם שדה Approval reason ופעולת Approve release.
- [ ] הצלחת אישור מעבדה, עם סטטוס התרומה והרכיבים הזכאים ששוחררו למלאי.
- [ ] דחיית תרומה: הודעת הצלחה וסטטוס Rejected.
- [ ] תיקון תוצאה עם סיבה, טבלת Result history המציגה את הגרסה הקודמת והחדשה, והחזרת רכיבים זמינים להסגר.

## 6. ניפוק שגרתי — Routine dispensing — DISPENSER

- [ ] טופס Request components, כולל מוצר, סוג דם, כמות ואסמכתה.
- [ ] דוגמת בקשה עבור כל מוצר: PRBC, FFP, Platelets ו־Cryoprecipitate.
- [ ] Review allocation עם הצעת הקצאה שניתן לספק וכפתור Confirm dispensing.
- [ ] הצעת PRBC הכוללת סוג דם חלופי תואם, אם ניתן להדגים בנתונים.
- [ ] Insufficient compatible stock עם הכמות הזמינה והחוסר, ללא כפתור אישור ניפוק.
- [ ] הודעת הצלחה לאחר אישור ניפוק.
- [ ] הודעת ביטול לאחר Cancel request.

## 7. ניפוק חירום — Emergency dispensing — DISPENSER

- [ ] טופס Emergency O-negative red cells, כולל המלאי הזמין, כמות ואסמכתה.
- [ ] אזור Confirm emergency issue לאחר Review request.
- [ ] הודעת הצלחה לאחר אישור ניפוק חירום והמלאי המעודכן.
- [ ] הודעת שגיאה כאשר מבקשים יותר ממלאי PRBC O− הזכאי הזמין, או כשהמלאי אפס.
- [ ] הודעת ביטול לאחר Cancel request.

## 8. ביקורת ורשומות — Audit & records — ADMIN

לצלם כל אחת מעשר האפשרויות בתיבת Record collection, גם אם אוסף מסוים ריק בנתונים הנוכחיים:

- [ ] Audit logs — יומן ביקורת.
- [ ] Donation records — תרומות.
- [ ] Blood components — רכיבי דם.
- [ ] Laboratory results — תוצאות מעבדה.
- [ ] Release decisions — החלטות אישור ודחייה.
- [ ] Issued components — רכיבים שקושרו לניפוק.
- [ ] Legacy blood units — מנות מהמודל הישן.
- [ ] Dispensing events — אירועי ניפוק.
- [ ] Issued units — קישורי מנות מהמודל הישן לאירועי ניפוק.
- [ ] Request receipts — קבלות בקשה למניעת פעולות כפולות.

מצבים נוספים באותו מסך:

- [ ] רשומה עם Details פתוח ו־Complete record מוצג.
- [ ] חיפוש וסינון תאריכים פעילים; ב־Audit logs גם Action ו־Outcome.
- [ ] שורות מסומנות, מונה בחירה וכפתור Export selected פעיל.
- [ ] הודעת הצלחה לאחר Export selected.
- [ ] הודעת הצלחה לאחר Export all matches.
- [ ] הודעת הצלחה לאחר Download full database.
- [ ] No matching records לאחר סינון ללא תוצאות.
- [ ] עמוד נוסף, אם יש יותר מ־20 רשומות.

## 9. קטלוג מוצרים — Product catalogue — ADMIN

- [ ] טבלת Versioned product policies, כולל גרסאות, ימים, בסיס תוקף ותנאי אחסון.
- [ ] טופס Create profile version עם מוצר ומשך חיי מדף.
- [ ] הודעת הצלחה והגרסה החדשה לאחר יצירת פרופיל.
- [ ] טבלת Storage locations.
- [ ] טבלת Required laboratory tests, כולל גרסת פאנל, סוג תוצאה וחובת ביצוע.
- [ ] טופס Publish new panel version עם קוד בדיקה נוספת וסיבה.
- [ ] הודעת הצלחה, הפאנל החדש ורשימת גרסאות הפאנלים לאחר פרסום.

## 10. ניהול משתמשים — User management — ADMIN

- [ ] סיכום TOTAL USERS וטופס Add New User.
- [ ] אפשרויות התפקידים ברשימת Role: OPERATOR, LAB, DISPENSER, ADMIN ו־RESEARCHER.
- [ ] טבלת User Directory עם אפשרויות שינוי תפקיד והפעלה או השבתה.
- [ ] הודעת הצלחה לאחר יצירת משתמש.
- [ ] שגיאה ביצירת משתמש, למשל שם משתמש שכבר קיים.
- [ ] משתמש לאחר שינוי תפקיד.
- [ ] חשבון מושבת עם כפתור Enable account וחשבון פעיל עם כפתור Disable account.

## סדר עבודה מוצע

1. התחברות, ואז OPERATOR: מלאי, קליטת תרומה, ייצור רכיבים ורכיבי דם.
2. LAB: תור עבודה, תוצאות, אישור, תיקון ודחייה. לצלם אישור לפני תיקון; להדגמת דחייה להשתמש בתרומה נפרדת.
3. DISPENSER: מלאי, ניפוק שגרתי וניפוק חירום. לצלם תצוגות מקדימות וביטול לפני ניפוקים שמקטינים מלאי.
4. OPERATOR: ייצור Cryo ופסילת רכיב, לאחר צילומי המלאי הנדרשים.
5. ADMIN: רשומות וייצוא, קטלוג וניהול משתמשים. לפרסם פאנל בדיקות חדש לאחר צילומי תהליך המעבדה הבסיסי.
6. RESEARCHER: מלאי והתפריט המוגבל.

המסכים המשותפים אינם מחייבים צילום מלא בכל תפקיד; לצילום הבדלי הרשאה, לכלול את התפריט ואת הפעולות הזמינות. מצבי LEGACY ועימוד מותנים בנתונים הקיימים. התחברות מחדש לאחר Sign out מחזירה למסך ההתחברות ואינה מסך נוסף. רוב האזורים הנפתחים מוצגים בתוך העמוד, ולכן חשוב לגלול אליהם.
