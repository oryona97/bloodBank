# הרחבת BECS: התחברות, הרשאות והגנת מידע אישי

הגרסה מוסיפה שלושה תפקידים ומגינה על הנתונים בשרת, תוך שמירת ממשקי קליטת התרומה, הניפוק הרגיל וניפוק החירום. מסד הנתונים הקיים נשמר; השדרוג מוסיף טבלאות ועמודות באמצעות migrations חדשים.

## מיפוי דרישות לפתרון

| דרישה | מימוש | ראיית בדיקה |
| --- | --- | --- |
| כניסה מזוהה למערכת | שם משתמש וסיסמה, hash מסוג scrypt, session בצד השרת | בדיקות login, סיסמה זמנית, תפוגה ויציאה |
| אדמין מגדיר משתמשים | יצירה, השבתה, החלפת תפקיד ואיפוס סיסמה | בדיקות API וניהול אדמין אחרון במקביל |
| אדמין צופה במטא־דאטה | מסך Users & audit עם מבצע, תפקיד, זמן, פעולה ופרטים | בדיקות הרשאות, שיוך מבצע וצפייה בדפדפן |
| עובד מפקיד ומושך דם | כל תהליכי BECS הקיימים זמינים ל־STAFF ול־ADMIN | 16 בדיקות התפעול הקודמות פועלות עם התחברות אמיתית |
| סטודנט אינו רואה פרטים אישיים | endpoint נפרד שמחזיר סיכומים בלבד | בדיקת כל שדות התשובה וחסימת API תפעולי וייצוא |
| שמירת Audit Trail | רישום פעולות מלאי באותה טרנזקציה, עם זהות המבצע | כשל בכתיבת Audit מבטל גם את התרומה |
| אי־שכתוב ההיסטוריה | אין פעולת עריכה/מחיקה; trigger והרשאות DB מוגבלות | בדיקות UPDATE, DELETE, TRUNCATE ו־ALTER אסורים |
| Copies of Records | ייצוא JSON מלא ותצוגה קריאה להדפסה לאדמין | בדיקת תוכן מלא ללא סודות התחברות |
| שימור נתונים ישנים | ללא שיוך בדוי למשתמש; רשומות ישנות מסומנות LEGACY | בדיקת שדרוג הסכימה והרצה חוזרת ללא שינוי נתונים |

## חלוקת ההרשאות

- **ADMIN:** מבצע כל פעולה תפעולית, מנהל משתמשים, קורא Audit ומייצא רשומות. גם לאדמין אין אפשרות לשכתב היסטוריה דרך המערכת.
- **STAFF:** קולט תרומות, מתכנן ומאשר ניפוקים ומוציא את כל מלאי O- בחירום. אינו מנהל משתמשים ואינו מייצא מידע מלא.
- **RESEARCHER:** קורא דוחות מחקר בלבד. אין גישה לרשומות תרומה, למלאי חי, לפעולות ניפוק, ללוג או לייצוא המלא.

השרת מחזיר 401 למי שלא מחובר ו־403 למשתמש ללא הרשאה. הסתרת כפתורים משפרת את הממשק, אך אינה מנגנון ההגנה היחיד. התפקיד וזהות המבצע נלקחים מה־session ולא משדות שהלקוח שולח.

## מידע אישי ונתוני מחקר

שם ותעודת זהות של תורם, תאריך התרומה וקישור לרשומת מנת דם אינם נשלחים לסטודנט. מסך המחקר מקבל שנה, סוג דם וספירה בלבד. קבוצה עם פחות מחמישה תורמים שונים, כולל אפס, מסומנת Suppressed. גם חמש תרומות מאותו תורם נשארות מוסתרות. אין סכומים משלימים או סינון חופשי שיאפשרו לחשב את המספר החסר.

הדוחות כוללים שנים שהסתיימו בלבד. לאחר פרסום שנה, הנתונים שלה אינם משתנים גם אם נוסף רישום מתוארך לאחור. כך מצמצמים הסקת פרטים אישיים מתוך השוואת תשובות בזמן אמת. בעת מעבר לשנה חדשה מצרפים רק שנים שלא פורסמו קודם.

מחיקת שם ותעודת זהות בלבד אינה מספיקה כדי להבטיח דה־זיהוי. מדיניות הסף בפרויקט היא בקרת פרטיות לצורכי המטלה, ואינה אישור משפטי לאנונימיות. ראו [הנחיות HHS לדה־זיהוי](https://www.hhs.gov/hipaa/for-professionals/special-topics/de-identification/index.html).

## שמירת Part 11

לוג התרומה והניפוק נשאר אטומי עם שינוי המלאי. נוספו מזהה המשתמש ותפקידו, תיעוד ניהול משתמשים, כניסות, יציאות, חסימות ובקשות ייצוא. סיסמאות ו־tokens אינם נכתבים ללוג. משתמש שנחסם או שינה תפקיד מאבד את ה־sessions הקיימים. בקשה חוזרת מזוהה גם לפי המבצע, כדי שלא תוחזר קבלה של משתמש אחר.

הייצוא המלא נשאר זמין לאדמין, ומתקבל מתמונת נתונים עקבית של PostgreSQL. הוא כולל את רשומות המקור, הקשרים לניפוקים, פרטי זהות המשתמשים והיסטוריית הביקורת. מידע אימות כגון hashes וסודות session אינו נכלל. לצד JSON יש תצוגה בפורמט קריא שניתן להדפיס.

בתיעוד הקודם שבפרויקט נדרשו Audit Trail ו־Copies of Records; שניהם נשמרו. הנוסח המלא של [21 CFR Part 11](https://www.ecfr.gov/current/title-21/chapter-I/subchapter-A/part-11) כולל גם דרישות נוהליות ודרישות חתימה כאשר חתימות אלקטרוניות רלוונטיות. התחברות אינה חתימה אלקטרונית. הפרויקט אינו מציג הצהרת הסמכה מלאה, ואינו מממש חתימות מחייבות, הכשרת עובדים או מדיניות ארגונית.

## הדגמה להגשה

1. להתחבר כאדמין ולפתוח Users & audit. להציג את רשימת המשתמשים ושלושת התפקידים ואת לוג הפעולות.
2. להתחבר כעובד ולרשום תרומה עם פרטים סינתטיים בלבד. להראות עלייה של יחידה אחת במלאי.
3. לתכנן ולאשר ניפוק רגיל; להראות שביטול תצוגה מקדימה אינו משנה מלאי.
4. לבצע ניפוק חירום ולהראות שרק O- מתרוקן, ולא ניתן לבצע ניפוק נוסף כשאין מלאי.
5. להתחבר כסטודנט ולהראות את הדוח המצרפי ללא פרטים אישיים וללא כפתורי ניפוק או ייצוא.
6. לחזור לאדמין, להציג ב־Audit את זהות העובד שביצע את הפעולות ולהציג עותק רשומות קריא.

הוראות התקנה, יצירת אדמין ראשון, הרשאות מסד הנתונים, בדיקות וגיבוי נמצאות ב־[מדריך ההפעלה](../../HIPAA_SETUP.md).
